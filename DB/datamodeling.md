데이터 모델링이란
- 데이터의 구조, 관계, 제약 조건을 표현하는 과정


데이터 모델링 기법
- ERD(Entity-Relationship Diagram): 엔티티, 속성, 관계를 사용하여 데이터 구조를 시각적으로 표현
- UML(Unified Modeling Language): 소프트웨어 개발에 주로 사용
- 데이터 흐름 다이어그램: 데이터의 흐름을 시각적으로 표현하여 데이터 처리 과정 분석

ERD의 구성 요소
- Entity: 데이터베이스의 관리 대상 - 고객, 제품 등
- 속성(Attribute): 엔티티에 대한 정보, 특징 - 고객의 이름, 전화번호 등
- 관계: 엔티티 간의 연결 - 고객과 주문 관의 1:N 관계 등

ERD 작성 단계
1. 엔티티 식별: 데이터베이스 관리 대상 파악
2. 속성 정의: 각 엔티티에 대한 정보 정의
3. 관계 설정: 엔티티 간의 연결 설정
4. ERD 작성: ERD 도구 사용하여 작성

ERD 기법의 장점
- 데이터 구조 명확하게 표현
- 개발자와 사용자 간 소통 원활하게 함
- 데이터베이스 설계 및 관리를 용이하게 함

데이터 모델링의 활용
1. 데이터베이스 설계: 데이터베이스의 구조 정의하고 최적화
2. 데이터 분석: 데이터 구조 이해하고 분석
3. 데이터 품질 관리: 데이터의 일관성과 정확성 보장

데이터베이스 모델링이란
- 현실 세계의 데이터를 컴퓨터가 이해할 수 있는 형태로 변환

데이터베이스 생명 주기
1. 요구사항 분석
2. 설계: 요구사항 분석 결과를 바탕으로 데이터베이스 구조를 설계. 개념적 / 논리적 / 물리적 3단계로 나뉜다.
3. 구현: 설계된 데이터베이스를 실제로 구축한다. DBMS를 사용하여 데이터베이스를 생성하고 테이블, 뷰, 인덱스 드으이 데이터베이스 객체 생성
4. 운영
5. 감시 및 개선

설계 단계
- 개념적 설계
    - 사용자의 요구사항을 바탕으로 데이터 모델을 추상적 표현(E-R 다이어그램)
- 논리적 설계
    - 개념적 설계를 바탕으로 데이터베이스의 논리적인 구조 구체화
    - 테이블, 컬럼, 데이터 타입, 제약 조건 등 정의
- 물리적 설계
    - 논리적 설계를 바탕으로 실제 구현 위한 물리적 구조 설계
    - DBMS 특징에 맞게 인덱스, 사용자 등 설정


발생 시점에 따른 엔티티타입 분류
- 기본 엔티티 타입
    - 시스템에서 가장 기본적인 데이터(사원, 부서 등)
- 중심 엔티티 타입
    - 기본 엔티티 타입과 연관
    - 핵심 업무에서 발생(주문, 계약 등)
- 행위 엔티티 타입
    - 시스템에서 발생하는 행위(주문내역, 계약세부내역 등)
- 약 엔티티 타입
    - 자신의 고유 식별자가 없고 다른 엔티티 타입의 식별자를 통해 식별된다

비식별 관계와 식별 관계
- 비식별 관계
    - 부모 기본키가 자식 일반 속성으로 전이
    - 점선으로 표현
    - 독립적 존재 가능
- 식별 관계
    - 부모 기본키가 자식 기본키로 전이
    - 실선으로 표현
    - 존재 종속적

병렬 관계
- 두 개의 엔티티 타입이 다른 엔티티 타입과 동일한 관계를 맺는 관계

슈퍼-서브타입 관계
- 하나의 엔티티 타입을 여러 개의 하위 엔티티 타입으로 분류하는 관계
- 배타적 관계 / 포함적 관계

속성
- 속성의 종류 
    - 기본 속성: 업무 분석 과정에서 도출된 속성(주문 날짜, 납기 일자 등)
    - 설계 속성: 데이터베이스 설계 과정에서 도출된 속성(주문 번호, 주문 상태 등)
    - 파생 속성: 기존 속성에서 계산 또는 변형하여 도출
- 약어 사용 금지
- 한 개의 엔티티 타입은 두 개 이상의 엔티티 집합이다
- 한 개의 속성은 오직 한 개의 속성값만을 가진다
- 서술격 및 소유격 형태는 피한다
